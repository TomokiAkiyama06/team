# API 費用の考え方（推定費用と実際の請求）

## 1. 既定モデルと単価

既定モデルは **Claude Sonnet 5.5（`claude-sonnet-5-5`）** です。単価は `config/pricing.toml` で管理しています。2026-10-20 に Anthropic 公式料金ページ（https://platform.claude.com/docs/en/about-claude/pricing ）と照合済みです。

| 項目 | 単価（USD / 100万トークン） |
|---|---|
| 入力 | 2.00 |
| 出力（思考トークンを含む） | 10.00 |
| キャッシュ書き込み（5分） | 2.50 |
| キャッシュ読み出し | 0.10 |

料金は改定されることがあります。導入時と学期ごとに公式ページと照合してください。

## 2. 1回の質問あたりの目安

| 内訳 | トークン数の目安 | 費用（Sonnet 5.5） |
|---|---|---|
| システムプロンプト | 約 1,500 | 約 $0.003（キャッシュ時は約 $0.0002） |
| 検索した資料（最大 12,000 文字） | 約 6,000〜10,000 | 約 $0.012〜0.020 |
| スレッド履歴（最大 6,000 文字） | 0〜5,000 | 0〜$0.010 |
| 出力（回答＋思考。effort=medium） | 約 800〜2,500 | 約 $0.008〜0.025 |
| **合計** | | **約 $0.02〜0.05** |

月額予算 $20 の場合、おおよそ 400〜1,000 回の質問に相当します。実際の値は資料の量と質問内容で変わるので、運用開始後に `利用状況` で実績を確認してください。

### 画像付き質問の追加費用

- 公式ドキュメント（Vision、2026-10-20 確認）では、画像は 28×28px のパッチ単位で数えられ、`⌈幅/28⌉ × ⌈高さ/28⌉` のビジュアルトークン（入力トークン）になります。
- ボットは送信前に長辺 1568px・約 120 万画素以下へ縮小するため、1 枚あたり最大約 1,600 トークン、Sonnet 5.5 の入力単価で **約 $0.003／枚** です（1000×1000px なら 1,296 トークン）。
- Claude 4.7 以降のモデルは長辺 2576px までの高解像度に対応していますが、ボット側で先に縮小するため、費用の上限は `IMAGE_MAX_LONG_EDGE` / `IMAGE_MAX_PIXELS` で決まります。
- 同じスレッドの追加質問では、保存期間内の過去の画像も再送するため、**質問のたびに画像分の入力トークンがかかります**。1 回に送る画像は `IMAGE_MAX_PER_REQUEST`（既定 6、最大 20）枚までで、今回の画像を優先し、残りを新しい履歴の画像から選びます。
- 予算の事前予約には、文字数からの見積もりに加えて画像の推定ビジュアルトークンを含めます。精算は API 応答の `usage.input_tokens`（画像分を含む実測値）で行います。
- `利用状況` には今月の画像付き質問の件数・枚数・推定画像トークンを表示します（費用は入力トークンに含めて計上）。
- 読み取れない画像だけの質問は API を呼ばずに理由を返すため、費用はかかりません。

## 3. ボットの「推定費用」の計算方法

- Claude API の応答に含まれる `usage`（入力・出力・キャッシュ書込・キャッシュ読込のトークン数）に、`pricing.toml` の単価を掛けて算出します。
- サーバー側フォールバックが動いた場合は、`usage.iterations` の試行ごとに、その試行を実行したモデルの単価で計算して合計します。
- 応答モデルが料金表に無い場合は、表の最大単価で保守的に計上します。

## 4. 予算超過を防ぐ仕組み（事前予約）

1. 質問を受け付けたら、Claude API に送る**前に**最大見込み額を予約します。
   - 予約額 ＝ 入力の見積もり（文字数 × `TOKEN_ESTIMATE_PER_CHAR`）× 入力単価 ＋ `CLAUDE_MAX_TOKENS` × 出力単価。プロンプトキャッシュが有効な場合は、キャッシュ書き込みの割増も含めます。
   - フォールバックを有効にした場合は、拒否された試行と代替モデルの試行の両方が課金され得るため、予約額を約2倍にします。
2. 次の式を満たさない場合は、API を呼ばずに断ります。
   `今月の確定額 ＋ 処理中の予約額 ＋ 今回の予約額 ≤ MONTHLY_BUDGET_USD`
3. 応答後に実際のトークン数で精算し、予約を解除します。
4. 予約額は上限見積もりなので、通常は実額より大きくなります。そのため、予算の残りが少なくなると、実際には収まる質問も断ることがあります（安全側の動作）。

## 5. 推定費用と実際の請求が一致しない理由

ボットが表示する金額は**推定値**です。実際の請求額は Anthropic Console（Usage / Billing）で確認してください。差が出る主な理由は次のとおりです。

| 要因 | 推定と実請求のずれ方 |
|---|---|
| このボット以外で同じ API キーを使った利用 | **ボットの上限・集計の対象外**（実請求のほうが多くなる） |
| 料金改定に `pricing.toml` が追従していない | どちらにも振れる |
| 実際の課金がないのに推定に計上する（出力前に拒否された一部カテゴリなど） | 推定のほうが多い（保守的） |
| タイムアウトなどで実使用量が不明なとき、予約額で計上する | 推定のほうが多い（保守的） |
| 通信エラーで応答を受け取れなかったが、サーバー側では処理されていた | 実請求のほうが多くなる可能性がある |
| 税・通貨換算・請求単位の丸め、クレジット・割引 | どちらにも振れる |
| Haiku 5.5 の 10万トークン超の割増、`inference_geo` の 1.1 倍、Batch・Fast mode | 本ボットでは発生しない構成です（使用していない） |

**上限はこのボット経由の利用分だけに適用されます。** 同じ API キーを別のシステムやスクリプトで使った分は、ボットの月額上限では止められません。API キーはボット専用に発行し、Anthropic Console のワークスペース単位の利用上限（Spend limit）も併せて設定してください。

## 6. サーバー側フォールバック（既定は無効）

`CLAUDE_REFUSAL_FALLBACK=true` にすると、安全分類器による拒否（`stop_reason: "refusal"`）のときに、API が別モデルで再実行します（beta 機能・`fallbacks: "default"`、ヘッダー `server-side-fallback-2026-07-01`）。

- **対応**: Claude API 上の `claude-sonnet-5-5` / `claude-opus-5-5` / `claude-opus-5` / `claude-fable-5-1`。それ以外のモデル（例: `claude-haiku-5-5`）では、設定が true でも送信しません（送ると 400 エラーになるため）。
- **Sonnet 5.5 の場合**: 代替モデルは Claude Sonnet 5 で、単価は同じです。再実行の対象は `cyber` と `frontier_llm` の拒否だけで、`bio` などは再実行されません。
- **追加費用**: 拒否された試行も課金される場合があります（出力途中での拒否、または `bio` / `frontier_llm` / `reasoning_extraction` カテゴリでの出力前の拒否）。その場合は、拒否された試行と代替の試行の両方が請求されます。
- **トークン集計**: 応答の top-level `usage` は最後の試行の分だけです。そのためボットは `usage.iterations` を合算して記録します。
- **注意**: beta 機能のため仕様が変わる可能性があります。授業 Q&A では拒否はまれなので、既定では無効にしています。
